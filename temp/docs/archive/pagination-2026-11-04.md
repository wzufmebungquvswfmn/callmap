# 任务查询分页（2026-11-04）

页面原来调用 `/v1/task-ids/collect`，需要收集结束后才能显示结果，超过默认 10,000 个任务或 100 页会整体失败。

页面现改用已有的 `/v1/task-ids/query`：

- 默认每页扫描 200 条，也可选 50 / 100；任务数可能因筛选和 session 排除而减少。
- 查询先显示第一页，下一页携带相同筛选条件、页大小与上游游标。
- 上一页及已经加载的下一页使用内存缓存；空匹配页仍按 has_more 允许继续。
- 翻页失败、取消或游标重复不会丢弃已有结果；可重试原游标。
- 修改条件、访问密钥或页大小后，旧结果过期，禁止继续翻页和导出，重新查询从第一页开始。
- 列表显示当前页，顶部显示已加载页的去重任务数，不宣称是上游总量。
- 复制、下载包含所有已加载页的去重 ID；未到末尾时明确提示尚未加载全部，下载名带 partial；到末尾后带 all。
- collect API 保持兼容，仍执行原有限额。单页接口的超时和排除查询保护仍然有效。

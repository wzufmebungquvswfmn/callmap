## 完整会话缺失的进一步核查

样本 `meta.projection.version=trace-metadata-only.v1`、`mode=metadata_only`，明确省略 `raw_spans`、`step_payloads`、`content` 等字段；`meta.redaction.level=metadata_only`。因此原始导出包含执行结构和统计，但没有完整会话正文。`source_complete=true` 只说明上游来源读取完整，不能把被投影隐藏的正文当作已返回。

进一步使用同一任务、同一服务账号请求 `/openapi/v1/task`、`messages_only=true`，实际返回 code=2002。完整正文读取需要核查 IAM `access_sensitive` 授权；不是增加 `include_raw_spans` 参数就能解决。

已修正：Trace 默认同时请求会话正文；过大时使用 OpenAPI inventory/票据分页；正文失败保留结构并明确报告。`execution_complete` 与 `conversation_complete` 分开，总 `complete` 仅在两者明确完整时为 true。导出增加 `conversation.json` 可用性/错误摘要，正文原始响应保存在 `conversation/`，即使只勾选 Trace 也执行正文读取。

## 服务账号权限申请后的重新验证

重新使用服务账号 secret 获取 IAM JWT 后，`/task` 的 `messages_only=true` 返回 available，scope 为 selected-session-message-text，样本公开消息计数 2。该模式明确省略 reasoning、工具、媒体、继承历史等，不应标为所有会话内容。

`include_trace=true` 的完整视图也返回 available，`meta.complete=true`、`completenessScope=trace-view`；样本覆盖 Mongo 256 spans、会话目录、公开消息及子 Agent 查询。仍不嵌入媒体、外部资源、容器日志和部分原始模型载荷等，具体范围原样保留于 meta。

`/trace/query` 请求原始 spans 的响应超过单次 100 MiB 上限。服务已适配：超限或上游 1005 时先回退同一 OpenAPI 的 read-model；只有任务数据仍不可用时再走 Fornax。仅拉 metrics 不再请求原始 spans。

仅改服务端和后端验证。Trace/导出增加 `conversation_mode`，默认 full 完整视图；messages 模式只读公开文本。新增返回字段供前端适配：`conversation.mode`、`completeness_scope`、`scope`、`coverage`、`omitted`、`resources_not_embedded`，以及 `raw_spans_complete` 和 `fallback_errors.openapi_raw`。
